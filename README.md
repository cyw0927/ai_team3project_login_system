# AX 수강생 평가 · 자동 팀 편성 시스템

Django + PostgreSQL 기반의 **수강생 평가, 결과 집계, 튜터 평가, Seed 기반 자동 팀 편성, 성장 관리** 통합 시스템입니다.

단순히 점수를 입력·조회하는 CRUD 프로젝트가 아니라, 실제 평가 운영 흐름을 하나의 서비스로 연결하는 것을 목표로 합니다.

```text
수강생 등록
→ 평가 회차·과제 운영
→ 학생 팀 평가 / 동료 개인 평가 / 튜터 팀 평가
→ 결과·순위 계산
→ 공개·보정
→ 누적 Seed 계산
→ 다음 회차 자동 팀 편성
→ 역량·성장 과제 관리
```

---

## 1. 프로젝트 핵심

### 평가 결과를 다음 팀 편성까지 연결

평가 결과가 한 회차에서 끝나지 않습니다.

- 학생이 다른 팀을 평가
- 같은 팀원이 개인을 평가
- 튜터가 각 팀을 별도로 평가
- 세 평가 결과를 가중치로 합산
- 최종 결과를 다음 회차의 Seed로 누적
- Seed를 이용해 새로운 팀을 자동 편성

신규 회차의 권장 기본 가중치는 다음과 같습니다.

```text
학생 팀 평가 40%
동료 개인 평가 30%
튜터 팀 평가 30%
```

과거 회차처럼 튜터 평가를 사용하지 않는 경우에는 기존 40:60 구조도 유지할 수 있습니다.

### 실제 데이터의 예외를 시스템 규칙으로 처리

AX2 공식 익명화 데이터 이관 과정에서 다음과 같은 실제 데이터 품질 문제를 다뤘습니다.

- 중복 응답
- 일부 결측 점수
- 동일 별칭의 서로 다른 팀 소속 기록
- 자기 팀 평가처럼 시스템 규칙상 유효하지 않은 응답
- 원본 응답과 시스템 계산용 데이터의 기준 차이

원본을 삭제하거나 임의 수정하지 않고 **raw archive를 보존**하면서, 화면과 결과 계산에는 규칙에 맞는 canonical 데이터를 사용하도록 구성했습니다.

```text
원본 데이터 보존
        ↓
식별·중복·소속 규칙 적용
        ↓
canonical 평가 데이터
        ↓
결과 계산 / 미제출 판정 / Seed 계산
```

AX2 데이터 기준으로 관리 명령을 이용해 개인평가 101건 + 팀평가 66건, 총 167건의 원본 응답을 재구축·검증할 수 있습니다.

> 아래 이미지는 README용 시연 캡처입니다. 실제 원본은 `docs/images/`에 저장합니다.

### 세 알고리즘 결과 비교

같은 28명을 대상으로 세 가지 방식을 각각 미리보기한 뒤 팀별 Seed 분포와 편성 결과를 비교할 수 있습니다. 현재 데이터에서는 Z식이 Seed 보유자의 팀 간 분산이 가장 균일해 우선 선택 대상으로 판단했습니다.

자동 편성은 결과를 즉시 저장하지 않고 **미리보기 → 비교 → 관리자 선택 → 확정** 흐름으로 운영합니다.

### 평가 회차 관리

- 회차 생성 / 수정 / 삭제
- 현재 회차 지정
- 시작 전 / 진행 중 / 종료 상태 관리
- 평가 시작 / 일시중단 / 재개
- 발표일 출결 관리
- 평가 시작 전 필수 조건 점검
- 평가 템플릿 재사용

### 과제 관리

- 팀 과제 / 개인 과제 등록
- 첨부파일 업로드·다운로드
- 팀·개인 제출 관리
- 제출 코멘트
- 과제별 역량 연결

### 학생 평가

핵심 평가 규칙:

- 자신의 팀은 팀 평가할 수 없음
- 다른 팀 구성원은 개인 평가할 수 없음
- 같은 팀 구성원만 개인 평가 가능
- 자기 자신은 개인 평가할 수 없음
- 동일 평가자·동일 대상 중복 평가 금지
- 결석/예외 출결은 제출 필요량 계산에 반영
- 제출 완료된 평가만 결과 집계에 사용

### 튜터 팀 평가

튜터는 학생과 동일한 팀 평가 문항을 이용해 각 팀을 **1~5점 척도**로 평가할 수 있습니다.

- 팀 단위 5점 평가
- 팀별 튜터 코멘트
- 여러 튜터 평가 가능
- 팀별 튜터 평균 계산
- 튜터 비중이 0보다 큰 회차는 튜터 평가가 제출되기 전 최종 순위 확정을 제한
- 저장 즉시 전체 결과 재계산

### 결과·순위

- 팀 평균 점수
- 개인 평균 점수
- 튜터 팀 평균 점수
- 가중치 기반 최종점수
- 경쟁 순위 계산
- 집계 제외 처리
- 관리자 보정점수
- 결과 공개 / 비공개 / 예약 공개
- 평가 패턴 검토
- Excel 결과 내보내기

관리자 보정은 원 평가점수와 별도로 보존하며, 0이 아닌 보정에는 사유 입력을 요구합니다.

## 4. 자동 팀 편성

현재 세 가지 자동 편성 전략을 제공합니다.

### Z식(Snake) 균형 배정

Seed 상위부터 순서대로 팀을 왕복하며 배치합니다.

```text
1 → 2 → 3 → 4
8 ← 7 ← 6 ← 5
9 → 10 → 11 → 12 ...
```

**장점**
- 상위 Seed가 특정 팀에 몰리는 현상을 강하게 억제
- Seed 보유자 수가 적어도 비교적 안정적인 균형
- 결과를 설명하기 쉬움

**단점**
- Seed가 없는 학생은 랜덤 요소가 남음
- 직전 성과가 강하게 다음 편성에 반영됨

현재 프로젝트에서는 **팀 간 Seed 균형을 가장 우선할 때 권장하는 방식**입니다.

### FIFA식 포트 배정

Seed 순위를 A/B/C/D 포트로 나눈 뒤 각 포트의 학생을 팀에 분산합니다.

- 포트 경계값을 직접 조정 가능
- 기본 누적 경계: 20 / 50 / 80
- 포트별 분산 상태 검토
- 특정 팀에 같은 포트가 몰릴 경우 관리자에게 경고

**장점**
- 상·중·하위 그룹을 직관적으로 섞을 수 있음
- 스포츠 드래프트처럼 설명이 쉬움

**단점**
- Seed 보유자 수와 팀 수가 맞지 않으면 포트 불균형 가능
- 경계 설정에 따라 결과 편차가 커질 수 있음

### 완전 랜덤

Seed를 사용하지 않고 활성 학생을 무작위 배정합니다.

**장점**
- 가장 단순하고 중립적인 방식
- 첫 회차처럼 Seed가 없을 때 적합

**단점**
- 실력 분포 균형을 보장하지 않음
- 우연히 상위권이 한 팀에 몰릴 수 있음

자동 편성은 즉시 확정하지 않고 **미리보기 → 검토 → 확정** 흐름으로 운영합니다.

## 5. Seed와 누적 성과

Seed는 이전 회차 결과를 다음 회차 팀 편성에 활용하기 위한 누적 지표입니다.

- 이전 평가 결과 기반
- 회차별 가중치 적용 가능
- 오래된 회차의 영향도를 낮출 수 있음
- 평가 결과가 없는 학생은 Seed 없음으로 표시
- Seed가 없는 학생은 편성 알고리즘에서 랜덤 요소로 처리

즉, 단순 랜덤 조 편성과 달리 **이전 프로젝트 성과를 다음 팀 구성에 반영하는 연속적인 운영 구조**를 지원합니다.

## 6. 역량 성장 관리

### 기본 과제 → 역량 반영

과제에 필요한 역량과 가중치를 연결할 수 있습니다.

```text
데이터 분석 과제
Python       40%
SQL          30%
데이터 분석   30%
```

회차 결과와 과제 성과를 이용해 학생의 역량 프로필을 갱신할 수 있습니다.

### 개별 성장 과제

- 연결 평가 회차
- 필요 역량 및 가중치
- 관리자 첨부파일
- 수행 단계
- 학생 자기진도 체크

## 13. 프로젝트에서 해결한 핵심 문제

| 문제 | 해결 방식 |
|---|---|
| 단순 평균만으로는 다음 팀 편성에 활용하기 어려움 | 결과를 누적 Seed로 변환 |
| 랜덤 편성은 실력 편차가 클 수 있음 | Z식 / FIFA 포트 / 완전랜덤 제공 |
| 한 가지 자동편성 방식만으로는 운영 상황 대응이 어려움 | 세 방식의 미리보기 후 관리자가 선택·확정 |
| 실제 평가 CSV에 중복·결측·소속 충돌 존재 | raw 보존 + canonical 데이터 분리 |
| 튜터 평가와 학생 평가를 구분해야 함 | staff 튜터 평가를 별도 집계하여 가중치 적용 |
| 평가 미제출자가 평균을 왜곡할 수 있음 | 완료 평가자 집합을 기준으로 집계 |
| 결과 공개 시점 통제가 필요함 | 즉시 공개 / 비공개 / 예약 공개 |
| 거대한 View 파일로 유지보수가 어려움 | 기능별 View + Service 계층으로 리팩터링 |
| 수동 테스트만으로 회귀를 놓칠 수 있음 | GitHub Actions로 check/핵심 테스트 자동화 |

## 요약

이 프로젝트는 **평가 → 결과 → Seed → 다음 팀 편성**을 하나의 사이클로 연결합니다.

학생 평가뿐 아니라 **튜터 평가, 결과 공개, 관리자 보정, 실제 CSV 데이터 정제, 세 가지 자동 팀 편성, 역량 성장 관리**까지 포함하며, 운영 규칙을 View 코드에 흩뿌리지 않고 Service 계층으로 분리하는 방향으로 리팩터링했습니다.
